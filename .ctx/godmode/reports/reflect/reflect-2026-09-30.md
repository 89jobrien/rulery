## Patterns & Surprises

### Took longer than expected

- **Writing the truth algebra's laws down.** I proposed absorption and distributivity as expected
  properties. proptest refuted both and produced the counterexamples. Absorption fails because
  `Unknown or Invalid` is `Invalid`; both distributivity directions fail because `and` is `min` under
  one total order and `or` is `max` under a _different_ one. Three attempts went into the second
  witness before proptest found the real one (`value=Unknown, left=False, right=Invalid`) — I had
  hand-computed a pair that agreed. Worth remembering: for a claim I can derive by inspection, hand
  derivation is slower and less reliable than letting the property test answer.
- **The O(n²) hunt.** The benchmark showed the cost; identifying it needed two controls. My first
  hypothesis — that `specs.clone()` contaminated the measurement — was wrong, and the control
  benchmark disproved it (identical numbers after switching to `iter_batched`). A second suspected
  site turned out not to be involved. The actual causes were a `BTreeMap` clone chain and
  `sort_by_key` recomputing its key per comparison; both matched the measured milliseconds to within
  a few percent, which is what made them identifiable at all.
- **The fixtures failed after passing.** Both new `examples/` fixtures passed their tests
  standalone, then failed the next full workspace run. The pre-commit YAML hook had rewritten them
  between the two runs. This was the most instructive failure of the session because it was invisible
  from inside any single command.
- **Nushell, repeatedly.** `2>&1`, `&&`, `||`, `mkdir -p`, `cp -R`, `for x in ...`, `ls -1`, and
  heredoc-in-command-substitution all failed at parse time. I burned several turns on this after
  having already learned each one earlier in the session.

### Discovered mid-session

- The four-valued algebra's two absorption orders disagree on exactly one pair (`Unknown` vs
  `Invalid`), which is the root cause of both failed lattice laws. The orders are now named constants
  with asserted `min`/`max` characterisations, so a future fifth value has to state where it lands.
- Six hand-maintained copies of two enums' variant lists across the property tests. Adding a variant
  would have left the build green with zero coverage. Fixed with `Truth::ALL` / `HashDomain::ALL` plus
  two assertions that turn the surviving gap from silent to loud.
- `xtask`'s `collect_test_names` reads literal `fn <name>(` source lines, because the spec's
  traceability tables name verification tests by source identifier. This is a hard architectural
  constraint against proc-macro-generated test names, and it is the strongest argument against `rstest`.
- The pre-commit hook already excludes `*HANDOFF*.yaml` for the same reason my fixtures broke
  ("indent style fights hj's serde_yaml output"). The conflict was pre-existing and known; I had not
  connected it to byte-exact fixtures.
- `criterion_group!` expands to undocumented functions, which `missing_docs` rejects. A written-out
  `main` avoids the macro with zero `#[allow]`s — consistent with this repo's rule that `#[allow]` is
  reserved for size and shape lints.

### Next session speedups

- **Read `~/.config/git/hooks/pre-commit` before checking in any generated or golden file.** It runs
  `prettier --write` over staged YAML and markdown and then `git add`s the result. Any byte-exact
  fixture needs a `.prettierignore` entry, and that will not be visible from a test run.
- **Nushell: write the correct form first.** The failures are parse-time, so they cost a whole turn
  each. `do { cmd } | complete` then `get exit_code` / `get stderr` is the reliable wrapper;
  `| complete | get stdout` for captured output.
- **Never write a commit message via heredoc in `$(...)`.** It expanded literally and committed
  `$(cat <<'EOF'` as the subject line. Write the message to `.ctx/_WORKING_DIR/` and use `git commit -F`.
- **When a test passes standalone but fails under `--workspace`, suspect cross-test interference or a
  hook, not the test.** The fixtures bug had exactly this signature.
- **`expect` in production code trips `missing_panics_doc`, and this repo has no `# Panics` sections.**
  Use `if let (Some(a), Some(b)) = (x.pop(), y.first())` instead.
- The deferred `extract.rs` robustness defect needs a fixture that produces an unpairable cell
  through some route other than a null record assignment. That fixture is the prerequisite; the fix
  is easy once it exists.
