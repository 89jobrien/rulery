# Plan: Rulery v0.1

## Context Map

### Current State

- The Rust 2024 workspace already contains the root `rulery` facade, all thirteen v0.1 crates, and `xtask`; every domain crate is an empty library shell, the CLI has an empty `main`, and only scaffold and basic xtask tests exist.
- `docs/specification.md` is the normative authority. The approved core design requires contract-first implementation; the approved xtask design requires one declarative workspace model, safe reconciliation, complete conformance checks, exact architecture validation, and fail-fast verification.

### Dependencies

- Dependency order is contracts; diagnostics, syntax, vocabulary, and store; IR; compiler and engine; scenarios and analysis; emit; facade; macros and CLI; conformance and xtask.
- The exact internal allowlist is the table in `docs/specification.md`: `rulery-contracts` has no Rulery dependency, `rulery-macros` has none, and `rulery-cli` depends only on `rulery` plus external `clap`.
- Store returns bytes and integrity, syntax parses, the facade assembles and remaps, compiler creates self-sufficient IR, engine evaluates it, scenarios and analysis consume it, emit renders typed artifacts, and CLI alone writes streams and files.

### Reference Patterns

- Preserve the existing thin `xtask/src/main.rs` and thin CLI binary pattern; application logic belongs in libraries.
- Use private invariant-bearing fields, checked constructors, custom deserialization through those constructors, deterministic `BTreeMap`/`BTreeSet` ordering, typed errors, and no unsafe code.
- Use `serde_jcs` only for canonical semantic payloads, `blake3` for hashes, `yaml-rust2` for strict YAML events and spans, `jiff` behind `TimeZoneDatabase`, and `rust_decimal` privately behind `DecimalValue`.

### Risk

- [ ] Public API names and signatures must match the normative declarations before v0.1 freezes them.
- [ ] All seven wire envelopes must reject unknown fields and schema tags without coupling language version to schema version.
- [ ] Rule identity and source order must never enter semantic precedence or hashes.
- [ ] Missing, null, malformed, Unknown, and Invalid must remain distinct through parsing, validation, evaluation, rendering, and analysis.
- [ ] Local import canonicalization must reject escape from allowed roots; source, import, expression, and analysis limits must fail deterministically.
- [ ] Trace and witness persistence must not expose case facts by default.
- [ ] `xtask bootstrap` must never replace unmanaged files, delete paths, or write in Check/DryRun mode.

## Goal

Implement the complete offline Rulery language version 1 and v0.1 Rust API, artifacts, CLI, fixtures, safety invariants, and conformance automation exactly as specified.

## Architecture

- `rulery-contracts` owns all evaluator-neutral boundary values: stable typed IDs, `QualifiedRuleId`, `FactPath`, exact decimal/date/time/duration values, source bundles/maps/spans, facts, outcomes, `Clock`, `TimeZoneDatabase`, integrity, hashes, and locks.
- `rulery-diagnostics` owns `DiagnosticCode`, the exact 40 definitions from `RUL001 SYNTAX_INVALID` through `RUL900 INTERNAL_INVARIANT`, validated diagnostics, labels, notes, help, typed evidence, non-overlapping fixes, properties, and `DiagnosticReportEnvelope`.
- `rulery-syntax` owns private YAML DTOs and returns `ParsedPackage`, `SourcePackage`, `SourceScenario`, `SourceCondition`, `SourcePredicate`, `SourceOperator`, and typed `SourceParseError`; it never creates diagnostics.
- `rulery-vocabulary` owns `ResolvedVocabulary`, `ResolvedRoot`, `ResolvedType`, `TypeDeclaration`, `OperationalTerm`, path resolution, and `FactState` validation.
- `rulery-ir` owns `Expr`, `Predicate`, `CompiledRule`, `CompiledDecision`, `CompiledPackageV1`, and `CompiledPackage`; compiler passes remain in `rulery-compiler`.
- `rulery-store` owns `PackageStore` and `FilesystemPackageStore`; the root facade owns `PackageAssembler<S, P>`, depth-first import traversal, lock policy, and package-global source-key remapping.
- `rulery-engine` owns `DecisionEvaluator`, complete traces, operator execution, strategy candidates, exact precedence keys, uncertainty relevance, conflicts, `SystemClock`, `FixedClock`, and `JiffTimeZoneDatabase`.
- `rulery-analysis`, `rulery-scenarios`, and `rulery-emit` own their specified ports, payloads, wrappers, and adapters. The facade composes workflows; the CLI owns command policy and I/O; macros expand only through validated constructors.
- Data flow is local files -> `LoadedSourceBundle` -> `ParsedPackage` graph -> globally remapped `CompilationInput` -> `CompiledPackage` -> evaluation/scenario/analysis artifacts -> typed renderer -> stdout or the three explicitly writable use cases.
- The seven envelopes are compiled package, decision trace, diagnostic report, rulebook lock, scenario result, analysis report, and decision table, tagged exactly `rulery.compiled-package/v1`, `rulery.decision-trace/v1`, `rulery.diagnostic-report/v1`, `rulery.rulebook-lock/v1`, `rulery.scenario-result/v1`, `rulery.analysis-report/v1`, and `rulery.decision-table/v1`.

## Tech Stack

- Rust 2024, MSRV 1.85, resolver 3, `cargo nextest`, rustfmt, Clippy with warnings denied, rustdoc, and property/compile tests.
- `serde`, `serde_json`, `serde_jcs`, `thiserror`, `blake3`, `rust_decimal`, `jiff`, `yaml-rust2`, `semver`, and `camino` for production contracts and adapters.
- `clap` is the CLI's only external direct dependency in addition to `rulery`; `syn`, `quote`, `proc-macro2`, and `proc-macro-crate` are confined to `rulery-macros`.
- `proptest`, `trybuild`, `insta`, `tempfile`, and `assert_cmd` support conformance; `pulldown-cmark`, `toml_edit`, `cargo_metadata`, `xshell`, `serde_yaml_ng`, `hex`, and `tempfile` support non-publishable `xtask`.
